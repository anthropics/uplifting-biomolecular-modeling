# BoltzGen kit — what changes vs stock

Stock = BoltzGen 0.3.2 at the pin (STOCK.md). Each lever is a module under `opt/forward/*/src` or `opt/host/*/src` that a kit mode puts on `PYTHONPATH`
and imports at start-up, patching one or a few stock classes in memory; `off` loads none. `design` under a kit mode launches the runner
`opt/forward/xattempt_addon/src/xa_run.py <run_dir> <seed>`; `BOLTZGEN_OPT=<mode>` / `boltzgen_opt.enable(mode)` import the same modules into the caller's
process. A mode is all of its levers: the sets below are `opt/boltzgen_opt/modes.py`, the lever descriptions `opt/boltzgen_opt/registry.py`, and the names
are the ones printed in `levers=` on the run's ACTIVE line. Both of stock's cuEquivariance call sites (triangle attention, triangle multiplication) run
unchanged in every mode; no lever replaces them and no mode binds a pairformer kernel from the shared core.

## exact — outputs identical to stock

Switches exported: `BG_GRAPH=graph XA_FAST_INIT=1 XA_HOIST=1 HL_ASYNC_WRITER=1`.
- `inproc` — the GPU steps of one configured job run in one process (one interpreter start, one model build per step, step *i* seeded N + *i*, matmul precision restored between steps); `analysis` / `filtering` stay stock subprocesses (`opt/forward/fast_inference/src/bg_inproc.py`, launched by `xa_run.py`). Numerics: bitwise. Steps aside: never.
- `graph_sampler` — design step: the per-step denoiser call of `AtomDiffusion.sample` captured once per shape into a CUDA graph and replayed (up to 16 graphs per process, least recently used evicted); the loop's random draws taken in stock order 32 steps at a time; the trajectory lists kept as host tensors (`opt/forward/fast_inference/src/bg_graph_patch.py`). Numerics: bitwise (same kernels, same order). Steps aside: a capture that fails prints `CAPTURE FAILED` → partial activation (§Every mode).
- `fastinit` — the `trunc_normal_init_` calls of model construction skipped under the strict checkpoint load that overwrites every parameter; coverage checked at load, deferred initialisers replayed on any other path (`opt/forward/xattempt_addon/src/xa_fastinit.py`). Numerics: bitwise. Steps aside: refuses, before the model loads, a model step whose data loader runs in the step's own process (`--num_workers 0`, `debug=true`) — skipping the initialisers' draws on NumPy's global stream would otherwise shift the in-process featurizer's stream from stock's.
- `hoist` — the diffusion transformer's step-invariant attention masks (the 24 token layers' and the atom encoder's / decoder's six windowed ones) built once per structure: one `(1, 16, N, N)` fp32 slice per token layer in a last-dimension-aligned buffer, broadcast over the diffusion batch through SDPA's strides; `AtomTransformer.forward`'s per-step `repeat_interleave` of the atom pair bias skipped (`opt/forward/xattempt_addon/src/xa_hoist.py`). Numerics: bitwise (same kernel, same values); an equality check on the first and last window row per layer disables the lever by name on a mismatch. Steps aside: a predict batch of several structures keeps stock's per-row tensors; at a diffusion batch of one design per structure (`--diffusion_batch_size` unset with fewer than 100 designs, `warm`'s one design) the equality check also compares the strides of the aligned slice with stock's contiguous tensor and disables the lever unless the token count is a multiple of 16 — the mode then refuses (`NOT ACTIVE`, exit 3); `--diffusion_batch_size 2` or more avoids it.
- `async_writer` — upstream's `DesignWriter` body runs unchanged on host copies of each batch's tensors in four forked worker processes while the next batch computes (the shared core's `opt_core.host.outputs.AsyncWriter`); drained at the predict loop's end, a failed write fails the run; the same files, names and bytes (`opt/host/writer_levers/src/hl_levers.py`). Numerics: none involved (output scheduling). Steps aside: never.
- seed hook (every kit mode; not a lever) — `opt/forward/fast_inference/src/bg_hook.py`, imported by that directory's `sitecustomize.py` in every process: seeds upstream's featurizer generator `np.random.default_rng(None)` from the seeded global NumPy stream's state without drawing from it (MT19937 key + position, hashed with the ordinal of the call under that key in the calling process — a forked DataLoader worker counts from its own first call, a re-seed opens a fresh count), and writes the run's timing records (`opt_timing.jsonl`). `off --seed` installs the same derivation in its stock child (`boltzgen_opt.stock_design.seed_default_rng`), so `exact` and `off` hand the featurizer the same generators and agree byte for byte on unconditional and structure-conditioned (binder) specs alike; without `--seed` a kit mode is not active.

## fast — within stock's seed-to-seed variation

Switches exported: `exact`'s plus `FL_COND_DEDUP=1 FL_ATTN_BF16=1 FL_ATTN_BACKEND=cudnn FL_DIT_FUSED=1`. All four levers live in `opt/forward/fast_levers/src/fl_levers.py`; `exact`'s five stay engaged.
- `cond_dedup` — inside the sampler, the conditioning upstream repeats over the B designs of a diffusion batch (`SingleConditioning`; each token layer's `AdaLN` s-path and sigmoid output gates) is computed on one row and broadcast as a stride-0 view (the shared core's `opt_core.capture.hoist.RowDedup`): same statements, GEMM row count N instead of B·N. Numerics: fp32 re-association from the changed GEMM shapes. Steps aside: a site that cannot de-duplicate names itself (`GATE-FAIL`) → partial activation.
- `attn_bf16` — the token transformer's pair-biased self-attention and the atom transformers' windowed (32 × 128) attention as one fused bfloat16 SDPA call with fp32 accumulation and fp32 output (the shared core's `opt_core.attn.sdpa_bias`, accounted per call by `opt_core.attn.size_gate`); the fp32 mask converted once per call and broadcast over the batch; projection GEMMs stay fp32 / TF32 as upstream ships. Numerics: bf16 rounding of the attention operands. Steps aside: a kernel the stack refuses → `attn_bf16 DISABLED reason=…`, the stock fp32 call serves → partial activation.
- `attn_cudnn` — pins `attn_bf16`'s call to torch's cuDNN fused-attention backend. Numerics: as `attn_bf16`. Steps aside: a pin the stack cannot honour is `attn_bf16 DISABLED reason=no_kernel:cudnn`, never another kernel unannounced.
- `dit_fused` — the 24 token `DiffusionTransformer` layers' fp32 elementwise statements around the GEMMs (AdaLN, the sigmoid output gates with their residual adds, the transition's SwiGLU over one concatenated GEMM) as fused row kernels fed `cond_dedup`'s one-row conditioning (requires it); the windowed atom transformers keep the stock statements. Kernel: the shared core's `opt_core.kernels` `dtk_kernels` (Triton, JIT-compiled for the visible card). Numerics: fused-kernel rounding in fp32. Steps aside: a kernel that does not import, compile or launch → `DISABLED` by name → partial activation.

## big — lowest peak GPU memory

Switches exported: `BG_GRAPH=off XA_FAST_INIT=1 XA_HOIST=0 SZ_TD_CHUNK=64 PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True HL_ASYNC_WRITER=1`. `inproc`, `fastinit` and `async_writer` as in `exact`; `graph_sampler` and `hoist` are off (their graphs and hoisted masks hold memory); one GPU, no multi-GPU form.
- `td_chunk` — `TokenDistanceModule` feature construction row-chunked over `SZ_TD_CHUNK` (64) rows instead of one dense `[B,4,N,N,161]` tensor; the same per-pair math (`opt/forward/size_levers/src/sz_levers.py`). Numerics: bitwise while the token-distance inputs are masked to zero (unconditional specs), the `design_iiptm` confidence field apart (summation order; not a ranking key of `final_ranked_designs/*.csv`); once a target structure makes those inputs non-zero (structure-conditioned specs) the TF32 products over 64-row blocks round differently from stock's one product over all rows — a numeric perturbation of `exact`'s outputs (a block covering all rows gives stock's bytes). Steps aside: never.
- expandable allocator segments — torch's `PYTORCH_CUDA_ALLOC_CONF` setting; no code.

## Every mode

- Out-of-memory trace (`sz_levers.py`, every kit mode): a CUDA out-of-memory inside `Boltz.forward` prints one `[sz] {"event": "oom", …}` line (the frames, the allocator high-water mark) and is re-raised unchanged, so upstream's own handler skips the batch exactly as stock does; every lever's fallback handler re-raises an out-of-memory error first (`opt_core.oom.is_oom`) — it is never absorbed into a fallback.
- Design census (`off` included): `[boltzgen-opt] DESIGNS step=<step> requested=<n> produced=<m> oom_skipped=<k> featurizer_skipped=<j>` after every `design` / `warm` run, and `designs` in `opt_manifest.json` — `requested` from the step's resolved config (`--num_designs` rounded up to whole diffusion batches), `produced` = the design CIFs this run wrote, the skipped counts from upstream's own warning lines; upstream exits 0 after a skipped batch, so the line states the shortfall, not the exit code.
- Accelerator census (kit modes): each model process prints `[boltzgen-opt <mode>] KERNELS route=… cueq_triatt=<word> cueq_trimul=<word> …` and `PEAK item=… alloc_gib=… reserved_gib=…` at exit (`opt/boltzgen_opt/census.py`: pass-through call counters on the two cuEquivariance dispatch functions; no clock; arguments and results untouched); `design` records them in `opt_manifest.json` under `kernels`. `off` prints neither.
- Refusals — every one is `[boltzgen-opt] NOT ACTIVE: <reason>` with exit 3, never a silent stock run. Before the run: the shared core off the `opt/pyproject.toml` `[tool.opt_core]` pin (checked first on every entry, `off` included), a lever directory or launch file missing, `boltzgen` not at 0.3.2, no visible GPU, no `--seed`, `--devices N > 1`, the cuEquivariance ops library not importable in a model process, `fastinit`'s loader condition above, and in-process a `Boltz` instance already built or a second mode. After the run — partial activation: a planned lever printed `DISABLED` / `CAPTURE FAILED` / `GATE-FAIL` or left no line showing it ran, so the mode refuses by name (`NOT ACTIVE: partial activation — <levers> fell back (…)`, `partial` in `opt_manifest.json`; the outputs under `--output` are not the mode's). Never a reason: the GPU model (one `NOTE gpu=… mem=…` line per process for a card other than the pinned H100 80GB HBM3, `gpu_gate=noted`, a remark below compute capability 8.0), the driver or library patch level, a cold JIT cache.
- Stock exceptions (STOCK.md §Stock exceptions) apply identically on every mode, `off` included; the kit has no opt-in upstream fixes.

## Switches

- `--mode` / `BOLTZGEN_OPT` select the lever set; there is no per-lever switch for callers: a caller-set `BG_*` / `XA_*` / `SZ_*` / `FL_*` / `HL_*` value is dropped at activation and named (`dropped=…` on the ACTIVE line). `--seed N` is the one flag that touches numerics (STOCK.md §How stock is run). Variable names and defaults: STOCK.md §Variables.
