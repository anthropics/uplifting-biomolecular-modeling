## 1. Kit files that restate, adapt or wrap upstream code

The files below are the kit's own; where they restate portions of an upstream method body they do so to rebind that method with a different
schedule, layout, precision or kernel, keeping upstream's arithmetic. The upstream licence texts (MIT; copyright lines above) are reproduced in
`third_party_licenses/joltz.MIT.txt`, `third_party_licenses/mosaic.MIT.txt` and `third_party_licenses/boltz.MIT.txt`.

Restating portions of **joltz** (`src/joltz/__init__.py` at the pin), MIT, `Copyright (c) 2024 Nick Boyd`:
- `opt/mosaic_opt/mosaic_fast/halfpair.py` — `PairformerLayer2.__call__` and `PairformerNoSeqLayer.__call__`, re-stated per pair sub-layer region (bfloat16 operands).
- `opt/mosaic_opt/mosaic_fast/memlevers.py` — the `TriangleAttention.__call__` preamble and the `Pairformer2` scan body (row-chunked attention, grouped rematerialisation).
- `opt/mosaic_opt/mosaic_fast/layer_unroll.py` — `DiffusionTransformer2.__call__` (its bias handling verbatim; the layer stack applied as a static loop).
- `opt/mosaic_opt/mosaic_fast/trimul_layout.py` — `TriangleMultiplicationOutgoing.__call__` / `TriangleMultiplicationIncoming.__call__` and their LayerNorm arithmetic (one channel-major layout).
- `opt/mosaic_opt/mosaic_fast/dead_template.py` — quotes the template-module lines of `Joltz2.trunk_iteration` / `TemplateV2Module.__call__` that it short-circuits when no template is staged.
- `opt/mosaic_opt/tests/test_levers_numerics.py` — restates the `Pairformer2` scan `body_fn` as the numerical reference the levers are tested against.

Rebinding or configuring **joltz** modules without restating their bodies: `opt/mosaic_opt/mosaic_fast/flashattn.py` (`TriangleAttention`, served
by a fused kernel of the shared core), `transition_fused.py` (`Transition`), `trimul_fused.py` / `trimul_provider.py` (the triangle multiplications,
through `trimul_layout.py`'s call), `precision.py` (matmul precision by region of the joltz model); `frozen.py`, `repro_cache.py` and `numstate.py`
reference no upstream code. joltz's modules are JAX translations of the boltz fork's torch modules (joltz's NOTICE); the boltz files behind the
triangle attention that `memlevers.py` restates in part and `flashattn.py` rebinds (`src/boltz/model/layers/triangular_attention/`) carry the
OpenFold / DeepMind Apache-2.0 headers quoted in §3.

Re-expressing the design recipe of **mosaic** (`examples/boltz_notebook.py` and `src/mosaic/models/boltz2.py` at the pin), MIT,
`Copyright (c) 2025 Escalante`:
- `opt/mosaic_opt/tools/recipe.py` — the notebook's recipe (its literals, each with its upstream source line, and its calls through mosaic's public API) as the one module every caller imports; `opt/mosaic_opt/recipe.py` is the package's accessor to it.
- `opt/mosaic_opt/tools/public_design_run.py` — the same recipe as a one-design-per-process script.
- both call mosaic's `simplex_APGM` (`src/mosaic/optimizers.py`), whose `projection_simplex` helper is the BSD-3-Clause routine named in §3; the kit files do not restate it.
- `opt/mosaic_opt/leverfiles.py` — copies the kit's `mosaic_fast/*.py` add-only into the installed mosaic package as `mosaic/fast/` (no upstream file is overwritten or removed).

Wrapping **boltz** (escalante-bio fork), MIT, `Copyright (c) 2024 Jeremy Wohlwend, Gabriele Corso, Saro Passaro`:
- `opt/mosaic_opt/mosaic_fast/fastload.py` — builds the torch `Boltz2` module with its random initialisers disabled before the strict checkpoint load (temporarily rebinding the initialiser functions during construction; the module code is upstream's, unmodified). The functions rebound are the `*_init_` functions of `src/boltz/model/layers/initialize.py` — the OpenFold-derived Apache-2.0 member named in §3 — and the names other boltz modules imported from it; none of their code is restated.
- `opt/mosaic_opt/weights.py`, `opt/mosaic_opt/tools/fetch_public_inputs.py` — call boltz's own `download_boltz2()` and check the checkpoint digest.

The template copies `opt/_build_backend.py` and `opt/mosaic_opt/_core_gate.py` come from this release's shared core (`common/opt_core/kit_template/`), not from a third party.

## 2. Model weights and data

- **Boltz-2** — `boltz2_conf.ckpt` (the checkpoint the recipe loads; sha256 pinned in `stock/PINS.json` "weights" and asserted at install and load), the CCD molecule library `mols.tar` (boltz's processed form of the wwPDB Chemical Component Dictionary, "the CCD data" in boltz's `main.py`; sha256 pinned in `stock/PINS.json` "weights".ccd and checked whenever it is fetched at install; wwPDB usage policy: https://www.wwpdb.org/about/usage-policies), and the affinity checkpoint `boltz2_aff.ckpt` (fetched by the same upstream call, never read by this kit, no digest recorded) are downloaded by boltz's own `download_boltz2()` from the public Boltz hosts (`model-gateway.boltz.bio`, then `huggingface.co/boltz-community/boltz-2`) into `$MOSAIC_CACHE_DIR/boltz/` at `./run.sh install --weights DIR` or first use. Terms: MIT per the Boltz README ("All the code and weights are provided under MIT license"); text `third_party_licenses/boltz.MIT.txt`. None of these files is in the release tree, the source archives or the container recipes.
- **ProteinMPNN** `v_48_020.pt` / `soluble_v_48_020.pt` (MIT) and **AbMPNN** `abmpnn.pt` (CC BY 4.0), and the **UniRef50-derived** `trigram_seg.pkl` (CC BY 4.0): carried exactly as committed upstream inside `stock/mosaic-70fec525.tar.gz` and installed with the mosaic package; terms and attribution as in the table above and in `third_party_licenses/ProteinMPNN-AbMPNN.NOTICE.txt` / `UniRef50-trigram-table.NOTICE.txt`.
- **Example input** — PDB entry 1BRS (barnase–barstar complex): the barstar chain D SEQRES (89 residues, the design target) and the barnase chain A SEQRES (110 residues, kept for provenance only) are inlined as sequence strings in `opt/mosaic_opt/tools/fetch_public_inputs.py`; the entry file itself is fetched from `files.rcsb.org` only by the input-fetch tool and is not carried in the tree. wwPDB archive data are free of copyright restrictions (CC0 1.0); usage policy: https://www.wwpdb.org/about/usage-policies.
- **No other data.** No alignment or MSA-database excerpt, structure file, trained test model or expected-output fixture is carried under this directory or inside the three archives (their only non-code members are the four files above, the licence / notice files and the packaging files); the package tests write their own short synthetic FASTA and a3m strings at run time.
