Files written for this kit that carry an in-file `SPDX-License-Identifier: Apache-2.0` line or an Apache-2.0 statement of their own
(`opt/forward/flashpairformer/third_party/fpf_smalln/__init__.py`, `…/fpf_pad8exact/__init__.py`, `…/fpf_cueq_pad8exact/__init__.py`, the sources
under `…/blockfuse_addon/`) carry no separate licence file: they are the kit's own code (Copyright 2026 Anthropic, PBC), under the Apache
License 2.0 like the rest of `opt/` (LICENSE in this directory). `opt/forward/flashpairformer/LICENSE` and
`opt/forward/flashpairformer/third_party/blockfuse_addon/LICENSE` are Protenix's licence text (ByteDance's copyright line), carried because
portions of those directories derive from Protenix v2.0.0 as the table above and the `NOTICE` beside each of them record; they make no
statement about the kit-written files next to them. `opt/forward/flashpairformer/third_party/**` is byte-pinned by the kit's tests
(`opt/protenix_opt/tests/test_sealed_third_party.py`), so a notice inside it changes only together with its pin; the kernel packages
`third_party/blockfuse_addon/NOTICE` credits by package name are the shared core's `common/opt_core/opt_core/kernels/fpf_mkpf`,
`fpf_triatt_pro`, `fpf_triatt_epi` and `fpf_triatt_k2b` (Apache License 2.0, `common/opt_core/LICENSE`), as `opt/forward/flashpairformer/NOTICE`
records.

Data files. Example inputs under `opt/forward/flashpairformer/public_inputs/` are the amino-acid sequences of PDB entry 1BRS (wwPDB archive
data, CC0 1.0) and single-sequence (query-only) `.a3m` files made from those sequences; they contain no third-party database sequences
(`public_inputs/PROVENANCE.md`). `opt/forward/flashpairformer/src/deadskip_manifest.json` is kit-generated data derived from the pinned
checkpoint: its sha256, and for each of the 41 sub-modules whose every parameter is below 1e-30 in magnitude the module path, class,
parameter count, largest parameter magnitude and the results of the zero-output probe — no weight tensors. `opt/forward/flashpairformer/
levers_addon/PTXV2_LEVERS_ADDON_v1/cueq_cache/*.json` are the kit-generated autotune tile choices described in the cuEquivariance row above;
`opt/forward/flashpairformer/CELLS.json`, `third_party/protenix_fpf_ditfast/CELLS.json` and `opt/protenix_opt/tests/data/*.json` are
kit-generated validation records. Model weights and data caches are not part of the tree or of the images built from it: `run.sh install
--weights DIR` fetches the six data caches with upstream's own downloader and transfers the checkpoint from upstream's download URL for the
pinned model name, comparing its sha256 with `stock/PINS.json` before it takes the checkpoint's name; upstream's server does not currently
serve the checkpoint (HTTP 403), so until it does a copy obtained from the upstream project is placed at `DIR/checkpoint/protenix-v2.pt` by
hand, and `install --weights DIR` digest-checks all seven files (README.md 'Setup', STOCK.md 'Pin').
