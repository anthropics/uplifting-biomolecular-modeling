# AtlasFold inference performance

This guide reports the inference memory and runtime measurements from the AtlasFold manuscript. These are profiling results rather than minimum hardware guarantees; device architecture, software versions, sequence composition, and inference options can change resource use.

## Profiling environment

All measurements were collected on one NVIDIA B200 GPU with CUDA 12.8. AtlasFold and AtlasFold-M used PyTorch 2.10.0 and cuEquivariance 0.10.0, with AtlasLM executed in BF16. These versions describe the profiling environment and are not package minimum requirements. Runtime excludes MSA-search time because AtlasFold inference does not perform an MSA search.

AtlasFold monomer profiling uses four recycles and its length-dependent 20/30/100-step diffusion schedule. AtlasFold-M profiling uses five diffusion samples, 10 recycles, and 200 diffusion steps. The reported length is the total number of residues, including all chains of a complex.

## Batched inference

AtlasFold and AtlasFold-M support length-bucketed, residue-budgeted batching. Increasing `max_tokens_per_batch` can improve throughput when multiple similarly sized targets are available, at the cost of additional peak memory. See [Batched inference](inference.md#batched-inference) for the API and batching semantics.
