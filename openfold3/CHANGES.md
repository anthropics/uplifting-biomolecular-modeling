# OpenFold3 kit — what changes vs stock

`opt/openfold3_opt/modes.py` is the one table of which levers each mode switches on and `registry.py` describes each lever; every run
prints one `LEVER name=… state=…` line per lever. A lever that meets a call it does not serve runs the stock statement for that call and
counts it by name (`fallback:<reason>=<n>`); a requested lever that cannot install makes the run exit 3 after the outputs are written.
Kernels come from the shared `opt_core` library, asked by a tier word (`exact`, `fast`, `big`): the library's per-GPU tables choose the
implementation per call class and the LEVER line names what served. The pair-stack kernels of `fast` and `big` are opt_core's
FlashPairformer kernels (`opt_core.attn.pair_fused`, `opt_core.kernels.trimul`, `opt_core.kernels.triattn`). Exact class = the stock
statement's operands, operations and order (bitwise); tolerance class = different rounding points, within stock's seed-to-seed variation.

## exact — outputs identical to stock

Every lever exact class; byte-identical to `off` (stock, STOCK.md §How stock is run) under `--det 1`. Runner YAML: the stock configuration, `stock_cueq_on_predict.yml`
(`stock_cueq_on_det_predict.yml` under `--det 1`).

- `fast_init`, `ckpt_mmap` — the random weight initialisation the checkpoint load overwrites is skipped; the checkpoint is read through the same `torch.load` call with `mmap=True` (a checkpoint torch cannot map takes the stock call, counted).
- `hostfeat`, `loader_workers` — two MSA-featurisation statements (`parse_a3m`, the `MsaArray` residue-index table) restated in numpy with identical arrays out (`OPENFOLD3_OPT_HOSTFEAT_PARTS`); the predict DataLoader gets `max(1, min(items, configured))` workers, seeded as stock seeds them (`OPENFOLD3_OPT_LOADER_WORKERS_CAP=none` keeps the configured count).
- `paircache`, `atom_hoist`, `apb_hoist` — step-invariant work computed once per rollout instead of per step: the diffusion transformer's conditioned pair representation and per-block pair biases (held head-major); the atom-attention encoder/decoder's reference-conformer embedding, pair activations and pair-bias projections in address-stable buffers (capped by `OPENFOLD3_OPT_ATOM_HOIST_MAX_GB`; under CUDA graphs the first step of each rollout runs eager to refresh them); `AttentionPairBias`'s key-mask bias memoised per pair-stack call.
- `templ_distinct`, `castcache`, `sync_hoist` — identical template rows pass the template pair stack once and are re-expanded before the stock reduction; bf16 copies of `Linear` / `LayerNorm` weights are memoised per module (refreshed when the fp32 tensor's storage or version changes); three per-recycle host read-backs of forward-constants (MSA depth draw, MSA row indices, distinct-template verdict) are served once per trunk call.
- `exactln` — OpenFold3's `LayerNorm` primitive bound to `opt_core.kernels.ln` on word `exact`: an NVRTC replica of ATen's LayerNorm kernel, served for a call class only where the library's table marks it bitwise and not slower on the running GPU and stack, and only after the first call per signature proved `torch.equal` in-process; ATen by name elsewhere.
- `triatt_exact`, `trimul_exact`, `trimul_form` — the pair stacks' cuEquivariance triangle-attention and triangle-multiplication calls bound to `opt_core.kernels.triattn` / `opt_core.kernels.trimul` on word `exact`: triangle attention is answered by the core's exact-class row — a fused kernel whose outputs are bit-identical to the engine's library call — for the pair stacks' calls on an H100 stack the core's table vouches for, and with the engine's own library call everywhere else: other cards and stacks, the template stack's calls, shapes outside the row's cells (issued one head at a time where the core's cell table says so — identical bits, less transient memory); triangle multiplication is served by the core's exact-class row per call class after a first-call `torch.equal` proof against the engine's statement on the call's own operands — a class whose bits differ is refused for the process by name and the engine's statement serves it. Bitwise the line without them; the LEVER lines name the rows served, the proofs and any refusal. `trimul_form` (the template pair stack's c_z 64 module statement, form `of3_module`) ships on no mode: `OPENFOLD3_OPT_TRIMUL_EXACT_FORM=1` arms it under the same proof.
- `transition_exact` — the trunk's SwiGLU transitions bound to `opt_core.kernels.transition` on word `exact` under this engine's statement form (`LigerSiLUMulFunction(linear_a(x), linear_b(x))` → `linear_out`), fed the module's own LayerNorm output; launched where the table names a kernel row bitwise for the call class on the running stack, the module's statement counted elsewhere (the c 384 single transition and the MSA transition always).
- `cuda_graphs`, `graphs_strict` — one denoising step captured per input shape and replayed for every other step and sample, and for later items with the same shapes (`OPENFOLD3_OPT_GRAPHS_KEEP=0` re-captures per item); on this mode up to 512 polymer tokens (`--graphs-max-tokens` / `OPENFOLD3_OPT_GRAPHS_MAX_TOKENS`), eager above and for queries without a readable token count, named on the ACTIVE line. Inside the graphed rollout the diffusion transformer's pair-bias attention runs stock's PyTorch path instead of the DS4Sci kernel (not capturable). `graphs_strict`: a capture failure fails the run rather than running eager.
- `post_release`, `postfwd_mem` — at ≥ `OPENFOLD3_OPT_POST_RELEASE_NTOK` (2400) tokens or below `OPENFOLD3_OPT_POST_RELEASE_MIN_FREE_GB` free, graph pools, cache buffers, cuBLAS workspaces and cached allocator segments are released after the sampler and after the item's forward (the next item re-captures); post-forward confidence scoring (pTM, PAE / PDE probabilities, all-atom frame differences) is computed per (sample, row block) under `OPENFOLD3_OPT_POSTFWD_MEM_MIB` into the engine's full-size tensors with every reduction left on them — the same bytes at a lower process peak (below 64 tokens and where `big`'s row-block scorer serves, the engine's statements run, named).
- `fastjson`, `writer_overlap` — the confidence-JSON writer's encoder replaced by a subclass that renders the same characters at C level (`OPENFOLD3_OPT_FASTJSON_ROUTE=stock` restores the stock encoder); item k's output files written by one forked writer worker while item k+1 is featurised and predicted (device→host copies stay on the main thread; the last item, feature/latent outputs and distributed runs write inline, named). Byte-identical files.

## fast — within stock's seed-to-seed variation

Tolerance class. Every `exact` lever except `exactln`, `triatt_exact`, `trimul_exact`, `transition_exact`, plus the levers below. Runner
YAML `fast_bf16_predict.yml`: upstream's DS4Sci and cuEquivariance kernel switches off (the cells take those call sites; a caller's
runner YAML that turns them on is refused) plus `bf16-mixed`.

- `trimul_v4`, `triatt_block`, `pair_transition` — `PairBlock`'s triangle multiplication (LayerNorm, gated projections, contraction, output projection as one fused kernel chain per direction), triangle attention (prologue LayerNorm → q‖k‖v‖g + pair bias, attention core, epilogue gate·o @ W_o added into z in place; the ending node reads zᵀ by address arithmetic) and SwiGLU transition (the hidden never reaches HBM; mask and residual folded) as FlashPairformer cells from `opt_core.attn.pair_fused`, in the pairformer, MSA-module, confidence and template pair stacks; a shape without a table row for the running GPU runs upstream's statement, counted.
- `triatt_provider`, `trimul_provider` — the attention core inside `triatt_block` and the triangle-multiplication row chosen per call class (GPU, dtype, head dim / channels, size bucket, direction) by `opt_core.kernels.triattn` / `opt_core.kernels.trimul` on word `fast`: prebuilt sm_90a / sm_80 extensions or Triton rows per the library's tables; a row that cannot serve on the running stack is refused by name and the table's named fallback serves, counted (`OPENFOLD3_OPT_PAIR_CORE=provider:<word>` / `OPENFOLD3_OPT_TRIMUL_WORD=<word>` pin a row).
- `ln_provider` — the LayerNorm binding of `exactln` asked with word `fast`: the library's fastest row inside each call class's tolerance band (Triton rows on the pair and MSA norms, ATen on small eager operands); a tolerance row's first call per signature is witnessed against the statement and a signature outside the bound retires to the statement by name.
- `apb_trunk` — the pairformer single track's attention with pair bias (trunk and confidence-head blocks): the bias produced head-major straight from `LayerNorm(z)` by `opt_core.kernels.ln_proj` and the attention as one launch of `opt_core.attn.apb_core` with the key mask and sigmoid gate fused (`OPENFOLD3_OPT_APB_TRUNK_PRODUCER=ln_proj|mm`, `_SCOPE=trunk+confidence|trunk`).
- `dit_glue`, `dit_attn` — the token diffusion-transformer block as one fused schedule: AdaLN as one row kernel, one q‖k‖v‖g GEMM, pair-bias flash attention over all samples in one launch reading `paircache`'s head-major bias in place, one output GEMM, fused conditioned transition (`OPENFOLD3_OPT_DIT_GLUE_ROWS=all|block`); `dit_attn` serves the attention calls `dit_glue` refuses by name. Both ask `opt_core.kernels.apb` by the mode's tier word (`OPENFOLD3_OPT_APB_TIER`; `OPENFOLD3_OPT_APB_WORD` pins a row).
- `atom_window`, `token_agg` — the sampler's sequence-local atom attention on two fused kernels (LayerNorm + AdaLN + q‖k‖v‖g with k/v computed once per atom; windowed attention with pair bias, gate, W_o, AdaLN-Zero gate and residual), TF32 dots with fp32 in/out (`OPENFOLD3_OPT_ATOM_WINDOW_PRECISION=tf32x3|ieee`), the launch tile per compute capability (`ln_tile=` on the LEVER line); the atom→token mean as one deterministic segment-reduce kernel. `opt_core.of3_sampler`.
- `templ_embed` — the template embedder's eight feature Linears + `linear_z(LayerNorm(z))` as one kernel with a single bf16 rounding, and mean over templates → relu → `linear_t` as one kernel (`opt_core.of3_trunk.templ_embed`).
- `rollout_bf16` — `diffusion_conditioning` and the token-level diffusion transformer under bf16 autocast; atom attention, coordinates and the sampler's arithmetic stay fp32. Trunk and heads run under upstream's `bf16-mixed`.
- `trunk_graph`, `tuner_guard`, `alloc_expandable` (exact class, carried here and not on `exact`) — `PairFormerStack.forward` captured into a CUDA graph per instance and input signature at its second call, up to `OPENFOLD3_OPT_TRUNK_GRAPH_NMAX` = 1024 tokens (eager above, under grad or after a failed capture, named); the chunk-size tuner re-tunes instead of raising when the confidence stack's call form changes within a process (`upstream_issues/OF3-005_chunk_tuner_rank_change.md`); `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`. `cuda_graphs` has no size cap on this mode.

## big — lowest peak GPU memory

`fast`'s numerics class. `fast`'s levers except `cuda_graphs`, `graphs_strict`, `paircache`, `atom_hoist`, `dit_glue`, `castcache` and
`trunk_graph` (each has a device-memory cost), with the providers asked by word `big` (the lowest-peak row per call class), chunk size
16 with the chunk tuner off (`big_bf16_c16_predict.yml`), plus the row-block units of `opt/forward/offload/`, each exact class on its own:

- `trimul_hostsnap`, `triatt_lean`, `trans_inplace` — triangle multiplication streams its update in row blocks (`OF3O_ROWS`) against a pinned host snapshot of the residual instead of a second device copy of z; the ending triangle attention uses one lean transposed buffer; the pair transition is applied in place.
- `input_rows`, `recycle_rows`, `templ_host`, `cond_once` — relative-position pair features, the recycling embedder's pair add and the template embedding built per row block (template features kept on the host, duplicates de-duplicated); the diffusion conditioning's pair path computed once per item and reused by every sample and step.
- `conf_chunked`, `confhead` — pLDDT / PAE / PDE / pTM computed over row blocks of the pair logits (`OF3O_CONF_ROWS`); from `modes.CONF_MIN_TOKENS` = 2048 tokens the PAE / PDE heads themselves are evaluated per row block (`confhead`, tolerance class), so the full `[S, N, N, 64]` logit tensors never exist.
- `bigln_guard`, `host_pool` — LayerNorm over ≥ 2³¹ elements applied in row blocks (the CUDA kernel's 32-bit index limit); the pinned host buffers the row units stream through, under `OF3O_PIN_BUDGET_GB` (a buffer over budget is pageable, with a NOTE line).
- Size gates, named on the ACTIVE and LEVER lines: below `OF3O_MIN_TOKENS` polymer tokens (`modes.OF3O_GATE_BY_CARD`, 1401 on the 80 GB cards) the row-block units step aside (`reason=of3o_gate`) and the item runs the `fast` composition minus the levers named above — a query set with members on both sides of the gate runs as two `run_openfold predict` passes into the same output directory (`ITEM GATE …` line); from `OPENFOLD3_OPT_REACH_GATE` tokens (`modes.REACH_GATE_BY_CARD`, 4500) the trunk's full-N² pair levers `trimul_v4`, `trimul_provider`, `triatt_block`, `triatt_provider`, `pair_transition` step aside (`reason=reach_gate`) and the row-block statements serve the trunk. Both take `<int>` or `none`.

### --n_gpu P

P = 2, 4 or 8 ranks of one node, `fast`'s numerics class. The launcher `tp.py` starts P `run_openfold predict` ranks (NCCL) and the adapter
`tp_rowpair/` binds OpenFold3's modules onto `opt_core.mem.rowpair`'s row-sharded statements. Runner YAML `big_bf16_c16_predict.yml`;
the other add-ons' switches are required unset (the sharded modules replace what they patch). P ∉ {2, 4, 8}, fewer than P visible GPUs,
or `--n_gpu` > 1 under another mode is refused by name; an input too small to shard runs on one GPU (`FALLBACK small_n_unsharded=1`);
one log per rank goes to `<output-dir>/_tp/`; under `--det 1` a replicated tensor that differs across ranks fails by name.

- `tp_shard_s` — the pair representation is born row-sharded (`z[:, r0:r1, :, :]` per rank) at the input embedder; template, MSA-module, Pairformer and confidence pair blocks run on each rank's rows with the peers' rows streamed; single, MSA and atom-level tensors are replicated; rank 0 featurises the query once and broadcasts the batch; output matrices are assembled on rank 0's host.
- `tp_triatt`, `tp_trimul` — triangle attention and multiplication per row block on `opt_core.mem.rowpair`'s fused kernels (bf16 operands, fp32 accumulation); pair blocks below the kernels' size floor and the c = 64 template pair stack run OpenFold3's torch statements, counted on the `TRIATT` / `TRIMUL` lines.
- `sample_loop` — the diffusion rollout and the confidence heads one sample per pass with every random draw made in stock order, so device memory does not grow with `--num-diffusion-samples`; each sample's structure is written as soon as the sampler returns (pLDDT column 0.00, a `_structure_first.json` sidecar) and overwritten by upstream's writer after the heads (`OF3TP_STRUCTURE_FIRST=0` keeps stock's order).
- `fast_init`, `loader_workers`, `fastjson`, `hostfeat`, `ckpt_mmap` — as under `exact`.

## Every mode

- No stock exception is applied (STOCK.md); the opt-in upstream fixes of README §Known upstream issues (`--upstream-fix <ID>`, modules under `upstream_issues/`) and the template guard (`TEMPLATES DROPPED`, exit 5) behave identically on every mode, `off` included.
- `--det 1` — the deterministic recipe (torch deterministic algorithms, `CUBLAS_WORKSPACE_CONFIG=:4096:8`, DS4Sci attention off, capture failures fatal) on every mode; the arithmetic of `off` and `exact` changes identically, which is why they agree bit for bit only when both carry it.

## Switches

- `MODEL_OPT_LEVERS_OFF=<lever>[,…]` — the selected mode without the named levers: `levers_off=<names>` on the ACTIVE / DRY-RUN / exit lines, `state=off reason=levers_off` on their LEVER lines; a name the mode does not carry is refused with the mode's lever list (exit 3); `graphs_strict` leaves only together with `cuda_graphs`; `big`'s row-block and row-shard levers are not subtractable; `off` ignores the variable. `--no-compile` — alias of `MODEL_OPT_LEVERS_OFF=compile`; a named no-op here (`compile=none` on every ACTIVE line), since no mode adds `torch.compile`.
- On no mode: `trimul_cueq` (`OF3T_TRIMUL=cueq`: triangle multiplication of the classes the pair cells do not serve through cuEquivariance's fused kernel instead of the module's statement; tolerance class) and `chunk_pin` (`OF3O_CHUNK`: a fixed chunk plan from the environment; `big` pins its plan through the runner YAML instead).
- Kit variables that change a lever's behaviour are named beside the lever above; the deployment variables and the two `big` gates with their defaults are STOCK.md's table.
